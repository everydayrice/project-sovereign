# Project Sovereign V0.2 Core Contracts

**Status:** implementation contract for the V0.2 alpha
**Machine-readable source:** [`contracts/v0.2/sovereign-core.schema.json`](../contracts/v0.2/sovereign-core.schema.json)
**Gateway operations:** [`contracts/v0.2/gateway.openapi.yaml`](../contracts/v0.2/gateway.openapi.yaml)

## Contract rules

- All primary IDs are opaque, Sovereign-issued identifiers. Callers must not infer tenant, provider, person, or authority from an ID.
- Every tenant-owned object carries `tenant_id`. A tenant filter is mandatory at repository and authorization boundaries; it is not a client-supplied convenience filter.
- `created_at`, `updated_at`, revision, status, and actor attribution are durable contract fields where the object is mutable.
- Provider, Surface, and Model are metadata associated with an Actor Instance. They do not determine its identity.
- Runtime indexes, cached orientation packets, embeddings, and derived views are not canonical records and must be rebuildable.
- Raw material belongs in an authoritative source system or protected object storage unless normalized content is approved for Intelligence.

## Identity and ownership

| Object | Owned by | Core relationship / lifecycle |
| --- | --- | --- |
| Tenant | Command | Isolation and configuration boundary. `active`, `suspended`, `archived`. |
| Principal | Command | Human, service, or extension identity acting within one tenant. |
| Provider / Surface metadata | Command registry | Describes an execution ecosystem and surface; reusable metadata, never actor identity. |
| Actor Instance | Control Plane | One independently operating chat/thread/run/workspace. Persists across Traffic Sessions when the adapter can carry its ID. |
| Traffic Session | Control Plane | One operational objective for one Actor Instance. Ends in `completed`, `cancelled`, or `stale`; checkout is not inferred as task completion. |
| Resource / Resource Claim | Control Plane | A generic managed-resource locator and a lease-bound intent against it. Claims move `planned → active → released` or `stale`. |

## Intelligence and Continuity boundary

| Object | Module | Canonical? | Promotion / revision rule |
| --- | --- | --- | --- |
| Canonical Intelligence Record | Intelligence | Yes | Immutable revisions; a new revision supersedes a prior revision only with provenance and Command authorization. |
| Source / Provenance | Intelligence | Metadata | Preserves authority, locator, retrieval time, content fingerprint, and supporting fragment. It does not itself grant authority. |
| Task Capsule / Session Capsule | Continuity | No | Mutable working state and resumability. It may reference canonical records but does not alter them. |
| Traffic Checkpoint | Continuity + Control Plane | No | Append-only material progress / handoff fact. It can be promoted only through a governed proposal. |
| Candidate Memory | Continuity | No | A proposed durable observation, decision, or constraint; never becomes canonical merely by persisting. |

## Resource and collision semantics

`Resource` is provider-neutral: repository, branch, path, pull request, database, schema, Worker/service, environment, document, campaign, SaaS object, or extension-defined type all use the same locator plus scoped attributes.

`ResourceClaim.intent` expresses activity: `observe`, `read`, `plan`, `write`, `merge`, `deploy`, `migrate`, `admin`, `destructive`, or a namespaced extension intent. A claim is coordination metadata, not ownership.

The default V0.2 evaluator returns one of:

- `safe` — no material coordination action; examples include concurrent reads and non-overlapping paths on distinct branches.
- `caution` — proceed with visible warning; examples include likely overlapping branch writes or stale traffic.
- `approval_required` — an exclusive/critical target is already active or policy requires a gate; examples include same-branch writes, same production deployment target, and same schema migration.
- `denied` — Command policy forbids the activity.

The result is recalculated when a planned claim becomes active. A stale claim remains visible for safety/history but never permanently locks a resource.

## Orientation and actor-directed retrieval

`ControlPlaneOrientationPacket` contains pointers and permits rather than a secretly minimized context payload. The actor chooses `lean`, `standard`, `broad`, `deep`, or `custom`, or issues direct authorized retrieval calls. The packet records that choice for observability only.

## Extension boundary

An `ExtensionManifest` requests scopes; an `ExtensionGrant` is the Command-owned, tenant-approved subset. Extension checks require an active installation and a non-revoked grant. First-party extension status has no effect on the authorization algorithm.

## V0.2 compatibility and changes

The contract namespace is `sovereign/v0.2`. Additive fields are allowed. Removing or changing the meaning of a required field requires a new major contract namespace and migration path.
