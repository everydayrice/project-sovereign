# Project Sovereign V0.2 Remaining Work

This is the exact continuation queue after the first Control Plane vertical slice. It is ordered to turn the proven in-memory lifecycle into a secure alpha, not to expand V1 scope indiscriminately.

## Required before any real alpha deployment

1. **Provision and verify dedicated infrastructure.** Confirm Project Sovereign’s dedicated Cloudflare Worker, PROJECT SOVEREIGN Neon project, R2 bucket, Neon Auth issuer/JWKS, and scoped secrets. Do not reuse RICE Lightning or RICE Command runtime resources.
2. **Implement Neon Auth verification.** Replace `failClosedAuthenticator` with JWT/JWKS validation, subject-to-Principal resolution, tenant membership/role checks, and revocation handling. Keep all Gateway routes fail-closed on any uncertainty.
3. **Run and verify `0001_foundation.sql`.** Execute only against the dedicated Neon project, verify RLS transaction settings, then add an integration test suite against an ephemeral/non-production Neon database.
4. **Replace the in-memory store.** Build transaction-scoped Neon repositories for Command, Control Plane, Continuity, Extensions, and Audit. The existing services must retain the same contracts and collision semantics.
5. **Bind R2 intentionally.** Add source-import and artifact adapters with encrypted object references, data classification, retention enforcement, content fingerprints, and deletion/retention audit behavior.

## V0.2 core completion after persistence

6. **Command completion.** Add role/permission evaluation, approval objects/workflow, tenant policy registry/editor, workspace containment (tenant remains the hard isolation boundary), source authority configuration, and provider/agent/tool registry UI/API.
7. **Intelligence completion.** Implement canonical record/revision/provenance/relation repositories, candidate-memory proposal/review/promotion, source resolution, live-authority freshness checks, and rebuildable retrieval indexes. Do not auto-promote Continuity.
8. **Continuity completion.** Persist Session Capsules, Candidate Memories, richer handoff acceptance/completion, task state transitions, waiting/snooze, and governed artifact links.
9. **Control Plane hardening.** Add Command-configured collision rules and approvals, policy audit detail, resource locator adapters, notification/webhook events, bounded stale-claim confirmation flows, and telemetry. Do not convert planned claims into global locks or auto-minimize actor context.
10. **Gateway parity.** Add MCP transport and CLI/admin tooling over the same services/endpoints; publish the JSON Schema/OpenAPI validation pipeline and version-negotiation behavior.
11. **Console shell.** Replace the static traffic-board page with the authenticated Console navigation: Home, Command, Intelligence, Control Plane, Continuity, Extensions, Integrations, and Audit/Health. Queue and Ideas remain external extensions.
12. **Extension Host completion.** Persist private/manual installation, grant/revoke credentials, event subscriptions/webhooks, launch metadata, uninstall retention actions, and audit. Do not build a public marketplace in V0.2.

## RICE alpha migration — only after core persistence and review

13. Build a read-only, exportable `rice-command` migration adapter with source repository/path/commit provenance.
14. Stage records by canonical Intelligence, Continuity, source/live authority, and superseded/obsolete history; require review before promotion.
15. Import into the RICE tenant configuration without adding RICE identifiers to generic schemas. Verify rollback/export and compare orientation-first retrieval with the former automatic-minimum-context behavior.
16. Run the real ChatGPT/Work/Codex bridge against actual concurrent sessions and repositories; measure collisions, handoff completeness, requested context depth, latency, rework, and acceptance before changing any default traffic or context policy.

## Explicitly out of V0.2 core

- Queue Tracker and Idea Tracker product UIs;
- Workforce;
- persistent Compute/workspace execution;
- a public extension marketplace;
- automatic context starvation/hidden minimum-context policy;
- generic deployment of RICE Command history without review.
