# Project Sovereign V0.2 Services and Storage

## Runtime shape

V0.2 is one dedicated Project Sovereign Cloudflare Worker with modular internal services. This is a deployable boundary, not a microservice architecture. The service interfaces below are in-process contracts so that persistent adapters, MCP, HTTP, and Console share the same policy and lifecycle semantics.

| Service | Owns | V0.2 boundary |
| --- | --- | --- |
| Auth/Security | verified identity, tenant context, scopes, tenant isolation | Gateway receives only verified `AuthContext`; the production Worker fails closed until Neon Auth/JWKS verification is wired. |
| Command | tenant, principal, policies, sources, provider/surface registry, extension grants | Defines policy; it does not own traffic or canonical record content. |
| Intelligence | canonical records, revisions, sources, provenance, relationships | Reads/writes are governed; large/raw payloads are locators rather than inline truth by default. |
| Continuity | task/session capsules, candidate memories, handoffs, material checkpoints | Explicitly non-canonical resumable state. |
| Control Plane | actor instances, traffic sessions, resources, leases/claims, collision evaluation, orientation | Check-in/orientation is intentionally inexpensive and does not auto-retrieve Intelligence. |
| Extension Host | manifest validation, installation state, scope checks, subscriptions | Delegates all permissions to Command; no privileged first-party path. |
| Audit | append-only attributable events | Receives significant state transitions from all services. |
| Gateway | HTTP/JSON, MCP, CLI/admin adapter translation | No provider-specific canonical model; routes call the same internal service contracts. |
| Runtime/indexing | cached orientation packets, search indexes, embeddings, telemetry | Rebuildable derivatives only. |

## API lifecycle for the first vertical slice

```text
verified identity
  → POST check-in / receive orientation + relevant traffic
  → POST claim (planned)
  → POST claim activation / re-evaluate collisions
  → heartbeat or checkpoint / renew lease
  → release claim(s)
  → checkout / record artifacts, blockers, next action
```

The local/test adapter supplies a verified identity only for deterministic tests. It is not an authentication shortcut for production. `src/worker.mjs` returns a fail-closed configuration error for protected routes until the dedicated Neon Auth verifier is connected.

## Neon data layout

`db/migrations/0001_foundation.sql` creates these logical PostgreSQL schemas:

| PostgreSQL schema | Plane / contents | Retention behavior |
| --- | --- | --- |
| `command` | tenants, principals, policies, provider/surface metadata, sources | durable configuration and authority metadata |
| `intelligence` | canonical records, immutable revisions, provenance, relationships | durable canonical state |
| `continuity` | task/session capsules, candidate memories, handoffs, checkpoints | durable non-canonical working state |
| `control` | actor instances, traffic sessions, generic resources, resource claims | high-churn but durable enough for recovery; active lease queries are indexed |
| `extensions` | extension identities, installations, grants | durable configuration and revocation history |
| `audit` | append-only events | retained according to Command policy |
| `runtime` | cache/derivative metadata only | safe to delete/rebuild |

All tenant-owned rows include `tenant_id`; the production adapter must set a transaction-local tenant setting and enforce RLS in addition to application authorization. Never accept a raw tenant ID as sufficient authorization.

## What goes where

| Storage location | Allowed content |
| --- | --- |
| Neon | normalized metadata, canonical records/revisions, Continuity state, traffic sessions/claims, audit, source locators, policy, extension grants. |
| Dedicated Project Sovereign R2 bucket | protected raw imports, large source snapshots where retention policy permits, artifacts that must be retained, encrypted payload envelopes/references. Metadata and hash remain in Neon. |
| External authoritative systems | live CRM state, deployments, Git repositories, databases, SaaS records, original documents, provider-native artifacts. Sovereign stores the source registration, authority designation, retrieval fingerprint/time, and locator. |
| Rebuildable runtime | embeddings, search indexes, cached orientation packets, telemetry aggregates. Their loss must not lose Intelligence, Continuity, source metadata, or audit history. |

- Run the migration against the dedicated Neon database and replace the in-memory repositories with transaction-scoped Neon repositories.
- Add Hyperdrive/connection-pooling and R2 adapters after the concrete Cloudflare resources are verified.
- Add MCP transport over the same Gateway operations; do not create separate traffic semantics.
- Implement the explicit, reviewable RICE Command import adapter with preserved repository/path/commit provenance and rollback export.
